# dsh-chat-edit · 对话编辑与删除

一个用于 DeepSeek Harness Web 界面的持久化插件（bundle）。它把「复制 / 编辑 / 删除」放到**同一条用户提示词的操作行**里，并允许**在当前对话内直接编辑**这条提示词：

- **编辑**：点击用户消息旁的铅笔图标，气泡原位变成内联编辑器（不是弹窗）。发送后，修改后的提示词作为**当前对话的下一轮**重新发送——**不新建会话、不新建分支、不产生归档副本**。本轮及之前的内容保留在上方，可回看。
- **删除**：点击垃圾桶图标，原位显示内联确认；确认后本轮及其之后的内容从当前对话中移除。删除仍采用「替换会话 + 归档原会话」实现，归档里会留一条旧副本（侧栏主列表仍只有一条对话）。

## 使用

安装并启用 bundle `dsh-chat-edit` 后：

1. 任意用户提示词下方会看到一条操作行：时间 + 复制 + 编辑 + 删除（编辑/删除与系统自带的复制图标并列）。
2. 点铅笔：提示词气泡原位变成编辑器，可直接修改；`Ctrl/Cmd+Enter` 或「发送」提交，`Esc` 或「取消」退出。
3. 点垃圾桶：原位显示删除确认；确认后生效。
4. 编辑/删除期间原文与操作行会暂时收起，避免误触；会话运行期间，已完成的旧轮次同样可以操作。

## 行为与边界

### 编辑（零分支）

- 编辑只调用 `session/prompt` 把修改后的提示词发送到**当前会话**，属于普通的新一轮；不 fork、不打开其他会话、不归档任何东西。
- 因此旧的那一轮（原提示词和回答）仍保留在对话上方；新的一轮追加在下面。会话日志是 append-only 的，DSH 没有“原地改写历史消息”的接口，这是唯一能完全避免新增会话/归档的做法。
- 如果发送失败，编辑器保留并显示错误，重试会再次发送。
- 编辑只发送文本；原提示词里的图片/文件附件不会随编辑重发，编辑器内会提示。

### 删除（替换 + 归档）

- 删除需要真正的“截断”，只能用替换实现：从本轮起点之前生成替换会话 → 清理继承的待发送消息 → 打开替换会话 → 沿用原标题 → 归档原会话。
- 侧栏主列表仍只有一条对话，但归档里会留下旧会话副本（可在侧栏「显示已归档」中看到并恢复）。
- 归档的原对话不能继续对话；工作区文件不会回退。
- 如果替换会话已创建但清理/打开失败，编辑器保留错误；重试复用同一条替换会话，取消会归档半成品，避免侧栏残留。
- 归档失败时页面底部会出现一次提示，侧栏可能暂时多出一条对话。

## 实现要点

纯浏览器侧插件（Host 半边没有行为），不依赖 `@deepseek-ai` 客户端包，只用平台提供的 React 与客户端服务：

| 位置 | 作用 |
|---|---|
| `conversation.chat.node`（keyed，key `user`，priority -1） | 替换用户消息渲染：复用官方 `conversation.chat.user.content` Factory 渲染内容，并在其后加上「时间 / 复制 / 编辑 / 删除」操作行与内联编辑器 |
| `shell.overlay`（list，id `chat-edit-toast`） | 归档失败等导航后失败的短提示条 |
| `ctx.remote.session.prompt` | 编辑：把修改后的提示词发送到当前会话；删除：在替换会话里不发送 |
| `ctx.sessions.fork` | 删除：从本轮起点之前的 `atSeq` 生成替换会话 |
| `ctx.remote.session.projections` + `updateQueue` | 删除：清理替换会话继承的待发送输入 |
| `ctx.remote.session.rename` | 删除：替换会话沿用原标题 |
| `ctx.uiWorkspace.openSession` + `archiveSession` | 删除：打开替换会话并归档原会话 |

删除的 `findForkBoundary` 会从 `turn/start` 往回跳过紧邻的 `agent/inbox/spliced` 提示词插入事件（切在插入之前，替换会话既不会重放旧提示词，也不会留下被 fork 关闭的空轮次），取前一个事件序号作为 `atSeq`；取不到时退回 `turn.start.seq - 1`，再由 inbox 清理兜底。

## 文件

- `index.js` — Host 半边（空实现，仅让 bundle 成为完整 Cordis 插件）
- `client.js` — 浏览器半边：用户行渲染、内联编辑器、编辑重发、删除替换/归档/清理逻辑
- `cordis.patch.yml` — 把 Host 行插入 profile 的 Loader patch
- `locale/en.json`、`locale/zh.json` — Plugin Manager 中的标题与描述
- `icon.svg` — 插件图标

## 已知限制

- 视觉验证受当前环境限制（无浏览器控制/截图能力）：已通过「槽位注册在运行中的页面里生效」、客户端模块加载、以及把真实 `client.js` 跑在 stub 客户端上下文中的 Node 冒烟测试（渲染用户行/编辑器、编辑走同会话 `session/prompt` 且零 fork/归档、删除的 `atSeq` 选择与 fork→清理→改标题→打开→归档顺序、失败重试、ESC/时钟）来验证；未做像素级截图核对。
- 替换用户行渲染器会覆盖官方用户消息行（`shadows-shipped-ui`）。实现复用官方 content Factory 并由本地错误边界兜底为纯文本，但仍可能与未来版本的官方行细节产生差异。
- 编辑不会改写历史：旧轮次仍可见，模型上下文也保留旧轮次。
- 删除会在归档里留下旧会话副本。
